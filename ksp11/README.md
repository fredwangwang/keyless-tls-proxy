# ksp11 — keyless PKCS#11 module for Linux (C + cgo)

A PKCS#11 v2.40 module that exposes **certificates from the keyless-tls-proxy
cert-server as token objects** and forwards every signing request to the server
over gRPC (mTLS). The private keys **never leave the server** — this is the
Linux counterpart of the Windows KSP DLL (`ksp/ksp.c` + cgo bridge), and lets
OpenSSL (via `pkcs11-provider`) use server-held keys with zero local key
material:

```
openssl ──PKCS#11──> ksp11.so ──tpmcert_*──> libtpmcertclient.so (cgo bridge)
                                                  │ gRPC (mTLS)
                                                  ▼
                                          cert-server (keys live here)
```

## Architecture

- `ksp11.c` — pure C PKCS#11 layer: slot/session/object/attribute handling,
  local hashing (SHA-256/384/512), DigestInfo parsing for raw PKCS#1, ECDSA
  DER→raw conversion. Contains no crypto keys and no gRPC code; it calls the
  bridge functions declared in `ksp/tpmcert_bridge.h`.
- `libtpmcertclient.so` — the cgo bridge (`internal/kspbridge`), built with
  `go build -buildmode=c-shared`. It reuses `internal/kspclient` (the same
  gRPC client the Windows bridge uses), loads the config, and implements
  `tpmcert_init` / `tpmcert_installed_count` / `tpmcert_get_installed` /
  `tpmcert_sign_hash`.

`ksp11.so` dlopens `libtpmcertclient.so` from its own directory at
`C_Initialize` time. The Go runtime must be loaded in **c-shared** mode —
linking a `c-archive` into a shared object that gets dlopened by a foreign
process crashes the Go runtime (`runtime.usleep`), which is why the bridge is
a separate `.so` rather than being statically linked.

## Build

```bash
make            # builds libtpmcertclient.so (cgo) + ksp11.so (C)
```

Dependencies: `gcc`, `libssl-dev` (cert parsing/hashing), `libp11-kit-dev`
(`pkcs11.h`), the Go toolchain, `openssl` 3.x + the `pkcs11-provider` package.

## Configuration

Read by the bridge at `C_Initialize` (env vars take precedence):

| Setting | Env | Default |
|---|---|---|
| server address | `KSP11_ADDR` | — |
| CA certificate | `KSP11_CA` | — |
| client certificate | `KSP11_CERT` | — |
| client private key | `KSP11_KEY` | — |
| JSON config file | `KSP11_CONFIG` | `$XDG_CONFIG_HOME/fredprx-ksp/config.json` |

The JSON file uses the same `{"addr","ca","cert","key"}` format as the
Windows bridge (`internal/kspclient.Config`). The TLS client identity
(cert/key) must be trusted by the cert-server's CA, exactly like the
Windows client.

## Test with OpenSSL (end-to-end)

```bash
make test       # runs test-sign.sh
```

`test-sign.sh` starts a local cert-server backed by the file store
(`sample-certs/`), points `pkcs11-provider` at `ksp11.so`, and verifies:

1. the provider loads a remote key via `pkcs11:token=ksp11-token;id=...`
2. RSA PKCS#1 v1.5 signing (`openssl dgst -sign`) + verify
3. RSA-PSS signing + verify
4. raw PKCS#1 via `openssl pkeyutl -sign` (module parses the DER DigestInfo)
5. ECDSA (P-256) signing + verify

Every signature is computed by the cert-server; the module only hashes the
input locally and relays the digest.

Manual run against a running server:

```bash
export OPENSSL_CONF=$PWD/ksp11.cnf      # generated by test-sign.sh
export KSP11_ADDR=127.0.0.1:50051
export KSP11_CA=.../ca.crt KSP11_CERT=.../client.crt KSP11_KEY=.../client.key
TP=$(openssl x509 -in server.crt -noout -fingerprint -sha1 | cut -d= -f2 | tr -d ':')
ID=$(echo "$TP" | sed 's/../%&/g')
openssl dgst -sha256 -provider pkcs11 -provider default \
    -sign "pkcs11:token=ksp11-token;id=$ID;type=private" -out sig.bin msg.txt
openssl dgst -sha256 -verify server-pub.pem -signature sig.bin msg.txt
```

## Implementation notes

- One token object per remote certificate with a private key
  (`CKA_ID` = SHA-1 thumbprint bytes, `CKA_LABEL` = subject; RSA modulus /
  exponent and EC params / point are parsed from the certificate DER).
- Signing mechanisms: `CKM_RSA_PKCS`, `CKM_RSA_PKCS_PSS`,
  `CKM_SHA{256,384,512}_RSA_PKCS[_PSS]`, `CKM_ECDSA`,
  `CKM_ECDSA_SHA{256,384,512}`. Digest mechanisms hash locally then forward;
  raw `CKM_RSA_PKCS` accepts DER DigestInfo (prefix stripped before
  forwarding); ECDSA signatures are converted DER→raw `r||s` because
  `pkcs11-provider` expects the raw form (see `convert_ecdsa_raw_to_der` in
  latchset/pkcs11-provider `src/sig/ecdsa.c`).
- `KSP11_DEBUG=1` enables call tracing on stderr.
